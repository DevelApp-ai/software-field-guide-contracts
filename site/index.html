Estate and Seam Contract Validator

Companion to The Software Field Guide, chapter “Segmenting the Estate”. Contracts are checked and requests decided in your browser by the same Rego policies the CLI runs — nothing is uploaded.

Paste an enclave contract as JSON — four answers plus a review date: enclave, owner, trustedIdentityPlanes, borderInventory, blastRadius, reviewedOn. Convert YAML with yq -o=json '.' enclave.yaml.

Paste a seam contract as JSON — six answers plus a rehearsal date: seam, enclave, entry, decision, monitoring, blastRadius, killPath, lastRehearsed, reviewDate.

Paste the whole estate as JSON: {"enclaves": [...], "seams": [...]}. This checks names are unique, every seam belongs to an enclave, and every border inventory entry has a seam contract behind it.

Answer one real 403: a request (subject, action, resource, context) decided against an authorization policy set. The trace names every rule considered and the criterion each non-firing rule failed on. Try the loaded example — a clerk charging without MFA — or flip mfa to true and watch the decision turn.

Lint instrumentation against three contracts — an event-name vocabulary, a metric label schema, and a cardinality budget — then gate a metrics export against the budget. The left editor holds the three documents; the right one holds the instrumentation scan and the observed label cardinalities. Budget findings cite the budget file they breach. Try the loaded example, then add {"metric": "storefront_requests_total", "label": "order_id", "distinct": 1204} to the observations and watch the budget break.

Gate an incident register against an alerting contract — a severity ladder with dated rungs, runbooks with escalation clocks, and alert rules with owners. Every fired alert must be claimed by an incident record, severities must be on the ladder as it stood at detection time, and postmortem actions must be verified closed. Try the loaded example, then add {"alert": "storefront-latency", "firedOn": "2026-10-15"} to the register's firedAlerts and watch the gate catch the alert that paged nobody.

Gate an agent manifest against the action registry — the micro-action vocabulary (named, typed, parameter-checked actions with execution envelopes under the platform ceilings, confirmation pinned to the severity classification) and the default-deny grants that claim it. The left editor holds the registry; the right one holds the manifest: agents pinned to rungs of the autonomy ladder, granted only declared actions, every argument scoped. Try the loaded example, then grant archive-reader the file-draft-chargeback action and watch the stage contradiction appear.

Judge a right-to-be-forgotten case against the DEK registry — the per-tenant key table where a destruction carries its evidence record. The gate demands a sweep record, an aged-out backup window, or an explicit pending reason for every store in the inventory; a live key is an erasure the registry still contradicts; a closed case with a pending store is a claim the evidence does not support. Nothing is forgotten without a record. Try the loaded example, then delete the postgres-replica-eu sweep record and watch the gate catch the replica nobody swept.

Gate N fabric renders and a promotion PR against the segment contract — one contract, then every fabric's rendered copy of it, then the flow evidence a promotion to enforce must cite. A rule missing from one render, a render carrying a rule the contract never had, a direction or type or port disagreement, a promotion claiming evidence nobody read: all caught. A rule nothing exercised is flagged for review, not failed — a dead rule is a review flag. A rule is not enforced until every fabric says so. Try the loaded example, then delete the cloud render of R2 and watch the gate catch it citing both files.

Gate a drill record against the ingress posture case — the DNS containment boundary (the zone), default-deny and the decision that backs it, the allowed domain patterns the zone can hold, the certificates with their rotation clocks, the SLOs with pagers behind them, the route classes the edge carries and the ones the audit logs, and the kill path the platform swears it can pull. A wildcard outside the zone, an allow list without the default, an expired certificate, a pager-less SLO, an unlogged route class, a kill path declared but never rehearsed: all caught. A certificate inside its rotation window or a rehearsal grown stale flags for review, not failure. Try the loaded example, then change the kill path's drill date and watch the staleness clock catch it.

Gate a citizen app manifest against its spec and the platform guardrail registry — the components the app ships and the behavior each declares, the data bindings and the rails they ride, the platform actions it uses, and the guardrails it builds against with their versions. An escape hatch (a binding that goes around the registry's rails), an action outside the spec's rails, a behavior without spec coverage, a guardrail below the platform floor: all advised, never blocked — the gate stays green with the advice on the record. A document the advisor cannot read is the one red it can show. Try the loaded example, then change a binding's rail to raw-sql and watch the escape-hatch advice land.

Gate a component package manifest against the component registry — the package as data: its name, version, and tier, the sha256 artifact digest it publishes, the signature and attestation recorded over that digest, its provenance, and the dependencies it pins by digest. An unregistered package, an artifact drifted from its registration, an unresolved dependency, a stale pin, and a customer-tier package depending downward: all refused — a conformance gate, not an advisor, and the package does not ship until the drift is fixed. The validator is honest about what it models: it checks the evidence facts are recorded and internally consistent, not that signatures are cryptographically valid. Try the loaded example, then change the package's version to 1.5.0 and watch the unregistered-package refusal land.

Gate the estate's render matrix against the component package manifest — one component's rendered copies, fabric by fabric: the fabrics it must cover, and each fabric's version, pinned sha256 digest, and the policy bindings it holds in force. A fabric on another release, a re-render that swapped the artifact, a declared binding a fabric never ran, a binding in force the package never declared, a fabric with no render at all, and a matrix for another component: all refused — a conformance gate, not an advisor, and the renders are not believed until every fabric agrees. Try the loaded example, then change one fabric's version to 1.3.0 and watch the version-skew refusal land.

The playground loads the validator from wasm/ next to this page. To run it locally from a checkout: make site and serve the site-build/ folder (wasm needs http, not file://). CLI equivalents: make check-enclave FILE=... for contracts, make explain-authz FILE=... for authorization decisions, make obs-demo for the observability lint-and-gate walkthrough, make alerts-demo for the alert-to-record linkage walkthrough, make actions-demo for the action scope walkthrough, make erasure-demo for the deletion evidence walkthrough, make segment-demo for the segment render-consistency walkthrough, make ingress-demo for the ingress hardening walkthrough, make citizen-demo for the citizen spec-rails walkthrough, make component-demo for the component package conformance walkthrough, make matrix-demo for the render-matrix consistency walkthrough.
